# 拼装缺口机制（重块 + 凹位 · 四件套）

> 提出：程序（DSH），2026-10-18 · **待团队确认**
> 效果图：`Doc/拼装缺口_效果图.png`（生成脚本 `Tools/Art/gen_fitpuzzle_sketch.py`）
> 跑通的截图：`Doc/拼装缺口_测试场景.png`
> 试验场景：`Scenes/Test_FitSocket.unity` · 冒烟测试 **15/15**
> 预制体（4 个，都在 `Prefabs/BrickCity/`）：`FitBlockTriangle` / `FitBlockRound` / `FitSocketTriangle` / `FitSocketRound`

---

## 1. 一句话

场上两块**很重的几何件**（三角块 / 圆球），闸门根部与天花板各有一个**形状对得上的凹位**。
常规形态下推 60 N **纹丝不动** —— 必须先用规则改世界（质量 / 摩擦 / 重力）把它们挪到位；
**入位即锁死**，两件都进 → 闸门抬起。

**2 块 + 2 槽 = 4 个组件。** 槽只认自己那个形状。

---

## 2. 为什么是「四件套」，不是「钥匙 + 门」

| | 钥匙 + 门（不做） | 四件套（本方案） |
| --- | --- | --- |
| 怎么算「拿到了」 | 碰撞 / 拾取判定 | 件**物理上真的到了**座位（位置 + 静止 + 形状） |
| 玩家要做什么 | 找到它 | **改变世界**（改重力 / 摩擦 / 质量）才挪得动 |
| 规则的作用 | 无关 | 直接作用在件上，和铁箱 / 石头同一条路，**零特判** |

核心：**件是普通 Dynamic 刚体**，规则对它生效的方式与对箱子完全一样 —— 这是「涌现」，不是又写了一个道具。

## 3. 四个组件

| 组件 | 类型 | 参数 | 行为 |
| --- | --- | --- | --- |
| **三角块** | `FitBlock`（Shape = Triangle） | 180 kg · 1.6 × 1.55 m · Dynamic · **冻结旋转** | 吃重力 / 质量 / 摩擦；收玩家推力（`IPushable`）；可站立（`IMovingSurface`） |
| **圆球** | `FitBlock`（Shape = Round） | 260 kg · Ø 1.2 m · Dynamic · **允许滚动** | 同上，但会滚（唯一允许滚的东西） |
| **三角凹位** | `FitSocket`（Shape = Triangle） | 闸门根部 · 开口朝右 · 容差 ±0.28 m | 只吃三角块；到位 → snap → 广播 `SeatedEvent` |
| **圆窝** | `FitSocket`（Shape = Round） | 天花板 · 开口朝下 · 容差 ±0.30 m | 只吃圆球；同上 |
| **机关** | `FitPuzzle` | 凹位数组 + 闸门 + 灯 + 按钮 | 两块都合体 → **按一次按钮**（`PressByContact`）/ 驱动 `ISwitchTarget` / `UnityEvent OnSolved` / 抬闸门 |

> `FitPuzzle` 的「按钮」语义：`_button` 拖一个 `CitySwitch`，解锁时调它的 `PressByContact()`（`IContactSwitch`）。
> 于是门 / 电梯 / 巨石那套**现成的按钮接线**直接复用，不用为拼装机关写新的驱动。
> 只想做点别的（放音效、开对话）就接 `OnSolved`（UnityEvent），不需要写代码。

### 四个预制体（`Prefabs/BrickCity/`）

| 预制体 | 里面有什么 |
| --- | --- |
| `FitBlockTriangle` | Dynamic 180 kg · `PolygonCollider2D`（1.6 × 1.55，尖朝上）· `RuleAffectedBody` · `FitBlock` · **红色积木三角**（sorting **5**） |
| `FitBlockRound` | Dynamic 260 kg · `CircleCollider2D`（r 0.6，**允许滚**）· **蓝色积木球**（sorting **5**） |
| `FitSocketTriangle` | `FitSocket`（吃 Triangle）· Trigger 盒 ±0.28 · **三角槽位**（与件同形同大 1.6 × 1.55，sorting **1**） |
| `FitSocketRound` | `FitSocket`（吃 Round）· Trigger 盒 ±0.45 · **圆槽位**（Ø1.2，sorting **1**） |
| `FitPuzzle` | **空物体 + 机关组件**：拖进关卡就行（凹位自动收集，门拖一下就能开） |

摆法：石块拖进关卡；凹位拖到**座位中心**，缺口朝向与件的推入方向对齐。

### 接线：两个都合体才开门（`FitPuzzle`）

1. 把 **`Prefabs/BrickCity/FitPuzzle.prefab`** 拖进场景（**不用**手工加组件）
2. `_sockets` **留空就行** —— 开局自动收集场景里所有 `FitSocket`（日志会打印收到哪几个）。
   一个场景里有多套拼装机关时才需要手动指定
3. 门的 `CityPathMotor` 拖到 **`_onSolvedTarget`**（`CityPathMotor` 实现了 `ISwitchTarget`，`SetSwitchState(true)` 就是开门）
   或者拖一个 `CitySwitch` 到 `_button`（那它会被「按」一下，走门 / 电梯 / 巨石那套现成接线）
4. `_gate` **留空** —— 那个字段是给「闸门自己升起来」用的，用来开门会变成整块板上升 2 米

⚠️ **别把门接到单个凹位的 `_onSeatedTarget` 上**：那是「这一个合体了」就触发，两个件会开两次门、也等于第一个就开。
要「两个都合体」，门只能接 `FitPuzzle`。

运行时会有进度日志：`已合体 1/2 —— 还差一个` → `已合体 2/2 —— 够了，触发`。
（自动收集会全收 —— 同场景放两套机关时，手动把各自的凹位拖进 `_sockets`。）
接错线（凹位少于 2 个 / 数组里有空 / 解锁后什么都没接）会在 `Start` 当场报警告。

**排序 1 < 5 是有意的**：槽位永远画在件下面，件一入位就**完全盖住**槽位 —— 看上去就是「填进去了」。
槽位的尺寸**等于件的尺寸**（三角 1.6 × 1.55、圆 Ø1.2），没有外框、没有底座。

### 美术：积木风

色板直接取 `Tiles/Regions/Brick*`（红 `248,82,70` / 蓝 `71,195,253`）。
件与槽位共用一套语言：**平涂 + 深色描边 + 底边一道暗面 + 顶边一道亮棱** —— 和区域瓦片是同一种「塑料积木」的读法。
槽位是**件的外形的淡白半透明剪影**（磨砂玻璃感）：白底 alpha ≈ 76、外圈亮边 ≈ 214、内圈 ≈ 126，
不挖深色空腔 —— 深色在深色关卡里会糊成一个黑洞，浅色反而更像「该往这儿放」。

| --- | --- | --- |
| `Art/Sprites/Brick/BrickTriangle.png` | 三角块 | 1.6 × 1.55 |
| `Art/Sprites/Brick/BrickBall.png` | 圆球 | Ø1.2 |
| `Art/Sprites/Brick/BrickSocketTriangle.png` | 三角槽位 | 1.6 × 1.55 |

四张都是**程序生成**的：`Tools/Art/gen_brick_fitpieces.py`，改色板 / 尺寸重跑即可（320px，4× 超采样）。
件的贴图自带颜色，所以 prefab 上的 `SpriteRenderer.color` 是白的 —— **不要**再乘色。

⚠️ 槽位只有**外观 + 触发盒，没有实体碰撞** —— 墙上的凹腔由关卡那面墙自己切（见 §6）。
槽位以**座位点为中心**，所以它的位置就是件的落点：摆的时候直接拖到「件该停的地方」。

> `FitBlock` 一个类、两个枚举值 —— 两者除了碰撞体和「能不能滚」之外没有差别。
> `FitSocket` 自带一个可选的 `ISwitchTarget`（与 `CitySwitch.FollowMotor` 同一个接口），
> 所以「拼上 → 开门 / 升降台」不用新写驱动代码。
> `FitSocket` 还有 `_seatParent`：凹位在会动的闸门上时填它，件会跟着门一起走。

## 4. 「拼上」的判定（两条，**不看速度**）

1. **形状对** —— 槽只认自己的 `FitShape`（给错件不报错、也不锁，就是拼不上）
2. **进圈了** —— 块心进触发圈，默认 ±0.45 m（2026-10-19 从 0.25 放宽）

→ 成立即 **snap**：改 **Kinematic** → 吸到座位锚点 → 不再吃推力 → 广播 `SeatedEvent`。

**⚠ 为什么不判速度**：早先要求「线速度 < 1 m/s 且连续 0.12 s 才算到位」，
结果是件在槽口来回蹭却永远不合体；而重力反转把球**甩**上去时速度本来就很大，那时正该合体。
现在进圈就合，代价是件会往外跳一小段到锚点（最多一个圈半径）。

**⚠ 圈的尺寸取触发盒的**世界**半尺寸**，不是字段原值 —— 凹位在关卡里套了 2× 缩放（很常见），
判定范围会跟着放大，否则大号的凹位会出现「块明明在缺口里却不算」。

**⚠ 为什么不用「碰撞体卡住」当判定**：Dynamic 刚体在凹槽里会抖、会被玩家的 `Slide` 顶出一点点、
会被别的刚体挤。纯碰撞卡不住「到位」，只能当**视觉**。

**⚠ 为什么 snap 之后变 Kinematic**：不然拼好的件会被后来的一次「重力 × 反转」弄走 ——
拼装成果必须不可逆。副作用是它留在 `Ground` 层，**玩家可以站上去 / 贴墙滑**（预期行为）。

## 5. 规则交互表（**实测数字**，不是估算）

| 规则 | 三角块（180 kg，平底滑动） | 圆球（260 kg，会滚） |
| --- | --- | --- |
| 质量 × 失效（×0.05） | 180 → **9 kg**，静摩擦 44 N < 60 N → a ≈ 1.8 m/s²，**推得动** ✅ 主解 | 变 13 kg，更好推 —— 但推得动也**举不起来** |
| 质量 × 反转 | 重的变轻，同效 ✅ 备解 | 同上 |
| 摩擦 × 失效（μ→0） | μmg = **0** → 60 N 推 180 kg，a ≈ 0.33 m/s²，**慢，但推得动** ✅ 备解（实测 2.5 s 走了 1.06 m） | 对球没用：滚不需要克服静摩擦 |
| 摩擦 × 削弱（μ0.15） | 0.15 × 180 × 9.81 ≈ **265 N > 60 N** → 还是推不动 ❌ | 对球没用（同上） |
| 重力 × 反转 | 会整个飞上去（**所以要先拼好**） | 井底直上 6.3 m，1.3 s 顶进圆窝 ✅ **唯一解** |
| 重力 × 失效 / 削弱 | 悬空漂着，没用 ❌ | 飘得慢，不好瞄 ❌ |

**这张表就是这套设计的价值**：同一对件，不同的规则各自只解决一部分 —— 玩家得**分开处理**，
而且**同一个件还能有两条路**（质量快、摩擦慢）。表里没有一条 `if`，全是物理自己算出来的。

### ⚠ 一条被实测推翻的设想：球不能靠「摩擦 × 削弱」从斜坡滚下来

原方案让球卡在 18° 斜坡上，靠静摩擦停着，μ 一降就滚。**实测不成立**：
球在斜面上**只要有一点初速就再也停不住** —— 静摩擦挡得住「滑」，挡不住「滚」；
斜坡上没有任何平衡位置（除非有滚动阻力或凹坑）。

现在的做法：**球开局就在井底**（1.5 m 深）。井是它真正的锁 —— 人够得着、推得动，但**举不起来**，
只有「重力 × 反转」能把它送上去。斜坡留着当落差与地形装饰。

## 6. 关卡布局（对应效果图 ①→④）

- **左**：闸门（3.2 m 高 × 2.92 m 宽，正好等于三角石板的右缘），根部切一个开口朝右的三角凹位 —— 三角块横推进去，**顶到斜面就到位**
- **右**：竖井 → 天花板圆窝 —— 球从井底被反转重力顶上去
- **中**：指示灯牌（▲ / ● 两盏），两块都亮 → 闸门升进门楣
- 三角块初始距凹位约 4.2 m；圆球初始在井底

**⚠ 2D 侧视里，横向的洞是穿透的**：▲ 件不能塞进 ▲ 洞（两边斜面互相顶住）。
凹位做成**沿插入方向扫过的囊**（左边是斜面、顶平、右边敞开），件滑进去顶死 —— 这才是能拼的几何。

### 与跳穿平台（OneWayPlatform）的关系

**件必须能从下面穿过跳穿平台**（关卡里的竖井多半是一层层的跳穿板，球得升上去）。
`OneWayPlatform` 原来只按**玩家**的位置开关整块碰撞体，对 Dynamic 的件就是一面实心墙。

现在：`OneWayPlatform` 遍历 `FitBlock.All`，对**每一对**碰撞体开关 `Physics2D.IgnoreCollision` ——
件朝上运动（`v · up > 0`）且还没整个越过时放行，停住 / 落下时恢复。

⚠️ 两条实测踩出来的约束：

1. **不能用 `collider.enabled` 管件** —— 那是整块平台的开关，件一穿就把玩家一起关了。
   `IgnoreCollision` 按「碰撞体对」生效，件和玩家各管各的。
2. **件要按平台自己的 `transform.up` 判，不能跟着重力翻**。
   平台的实心面默认「背着重力」，重力一反转实心面就跑到下面去了 —— 从井底升上来的球会**正撞实心面**，
   怎么调都过不去。对件来说语义只有一条：**从下面顶上来就放行，落到上面就接住**。

3. **放行条件必须带「正在上升」**，只看位置不行：接触点恰好等于「件心越过平面」那一刻，
   恢复碰撞会把件卡进面里（实测球停在平台下沿、速度归零，再也上不去）。

试验场景的竖井里放了一块跳穿平台专门验这条，冒烟测试因此多了一条断言（**15/15**）。

## 7. 实现约束（踩了就废）

| 约束 | 原因 |
| --- | --- |
| 块必须是 **Dynamic** | 只有 Dynamic 吃 `Physics2D.gravity` 与 `Rigidbody2D.mass`。换 Kinematic / Static，「重力 × 反转」「质量 × 失效」**直接对它失效** |
| 必须挂 `RuleAffectedBody` | 质量规则靠它把倍率写进 `mass`；摩擦规则靠它克隆独占材质 |
| 必须放 **Ground(8) 层** | 玩家 `Slide` 与接地探测只认这一层 |
| 圆用 `CircleCollider2D` + 不锁旋转；三角用 `PolygonCollider2D` + `FreezeRotation` | 三角滚起来会翻面，缺口就再也拼不上 |
| `RigidbodySleepMode2D.NeverSleep` | 睡着的刚体**不响应重力变化**（同铁箱） |
| 圆窝材质 `bounciness = 0` | 球是撞上去的（上升 6.3 m，v ≈ 11 m/s），有弹性就会弹出来 |
| 摩擦材质用 `StoneMaterial2D`（Combine = **Minimum**） | 与地面取平均会把 μ 抬回去，「摩擦 × 失效」就失效了（同 ⑬ 石头踩过的坑） |

## 8. 风险 / 软锁

- **翻重力时场上其他重物会跟着飞** —— 顺序上先拼三角（入位即 Kinematic），或给它头顶加天花板罩住
- **玩家站在井口会挡住球** —— 保留，这是好玩的涌现（「站开点」）
- **球必须先停稳**（井底小平底），否则反转重力会斜着飞出井口
- **掉出关卡**（低于**出生点 30 m**）→ 2 s 后回出生点、清速度。
  ⚠️ 这个阈值是**相对出生点**的，不是世界坐标 —— 本工程的关卡在 y ≈ -28 ~ -41 一带，
  早先写死 `_killY = -20`，整关的件都被判成「已掉出」，每 2 秒被拉回出生点
  （表现就是「开了重力反转之后闪回原点」，2026-10-19 修）
- **件被卡在挪不动的地方**：目前只能靠玩家再上规则；要不要加「长按 2 s 重置该件」**未定**
