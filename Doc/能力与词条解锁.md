# 能力与词条解锁（2026-10-19）

> 一句话：**能力是玩家实体上的位标记，规则是「属性 × 关系」的交叉积，宝箱只是写入源之一。**

## 1. 能力锁

### 1.1 数据

`PlayerAbility`（`Gameplay/Player/PlayerAbility.cs`）是位标记：

| 位 | 能力 | 锁住时 |
|---|---|---|
| `WallClimb` | 贴墙下滑 + 蹬墙跳 | `WallClimbEnabled` 为 false，滑墙与蹬墙一起失效 |
| `AirJump` | 二段跳 | `MaxAirJumps` 按 0 打包，地面跳 / 土狼跳不受影响 |
| `Attack` | 轻击 / 重击 | 攻击输入被吞掉，攻击盒也不会扳开关 |
| `Throw` | 纸飞机飞刀 | `ThrowKnife` 直接返回 |

能力本身仍是**实体自己的序列化字段**（`_maxAirJumps` / `_wallClimbEnabled` / 攻击参数 / 飞刀预制体），
`_unlockedAbilities` 只是闸门。敌人配了对应字段就有，不受玩家解锁进度限制。

### 1.2 三个读取点

| 位置 | 代码 |
|---|---|
| `PlayerController.BuildTuning` | `MaxAirJumps = HasAbility(AirJump) ? _maxAirJumps : 0`；`WallClimbEnabled = _wallClimbEnabled && HasAbility(WallClimb)` |
| `PlayerController.FixedUpdate` ③′ | `bool attackPressed = input.AttackPressed && HasAbility(Attack);`，轻重击都用它 |
| `PlayerController.ThrowKnife` | 开头 `if (!HasAbility(Throw)) return;` |

`MaxJumps` / `JumpsLeft` 也走同一个判断，HUD 不会显示「还有 2 段跳」。

### 1.3 默认值

- 代码默认 `_unlockedAbilities = All`：现有测试场景（`Test_RuleSystem` 等）不会因为新字段没序列化而突然全锁。
- **正式开局**由 `GameRoot.StartStreaming` 调 `PlayerProgress.StartNewGame()`，把能力设成 `None`。
- 调试场景通常不经过 GameRoot，所以保持全开。

## 2. 规则锁

`PlayerProgress`（挂在玩家身上）实现 `IRuleUnlocks`：

```text
IsUnlocked(attr, rel) = attr ∈ 已解锁属性 && rel ∈ 已解锁关系
```

开局默认：

- 属性：`Gravity`
- 关系：`Revert`

所以只有 **重力 × 反转**。之后每个宝箱解锁**一个属性**或**一个关系**：

- 解锁「摩擦」属性 → 摩擦 × 反转 可用；
- 解锁「质量」属性 → 质量 × 反转 可用；
- 解锁「失效」关系 → 重力 × 失效、摩擦 × 失效、质量 × 失效……都可用了。

规则轮盘不用改：`RuleSelectionSession` 每次实时查 `IsUnlocked`，没解锁的属性只是 `unavailable` 灰化
（`RuleFan.SetAvailable`），不会被隐藏。

## 3. 宝箱

`CityRewardSource` 新增：

| 字段 | 用途 |
|---|---|
| `OpenByAttack` | 勾上 = 必须被攻击盒 / 飞刀打中才开，E 键无效 |
| `Kind` | `Ability` / `RuleAttribute` / `RuleRelation`（枚举只在末尾追加） |
| `Ability` | `Kind = Ability` 时给哪项能力 |
| `Attribute` | `Kind = RuleAttribute` 时解锁哪个属性 |
| `Relation` | `Kind = RuleRelation` 时解锁哪个关系 |
| `SourceId` | 每个场景实例唯一；玩家账本用它记账，回溯不会重复领 |
| `Receiver` | 留空自动找玩家身上的 `PlayerProgress` |

Inspector 由 `CityRewardSourceEditor` 接管：只显示当前 `Kind` 真正用得到的字段
（能力 / 属性 / 关系三选一），底部写一句「当前奖励是什么」；`SourceId` 为空或能力没选会直接给警告。
不会再把三个字段并排摆着让人以为都要填。

攻击入口走 `IContactSwitch.ImpactByContact`，与按钮 / 拉杆同一条路，**不进伤害管线**——
所以「伤害 × 失效」不会把宝箱一起锁掉。

流式加载回来的宝箱会在 `Awake / Start` 用 `PlayerProgress.IsClaimed` 回填「已开」视觉，
不会出现「看起来关着、按 E 没反应」。

## 4. 剑

`SwordInStone` 新增：

- `_requireFreeRule`：默认勾上 = 要求「摩擦 × 反转」；`BoulderSwordMechanism.prefab` **已改成 `0`**
  —— 石头碎掉、剑露出来之后，玩家走进 1.6 米就自动拔，不需要摩擦、也不需要攻击键。
- 其他剑如果还想吃摩擦规则，把 `_requireFreeRule` 勾上即可。
- `_grantAbility`：拔出时解锁哪项能力，默认 `Attack`。走 `PlayerProgress.UnlockAbility`，与宝箱同一个入口。

> 开局链路现在是通的：**重力×反转 → 砸碎巨石 → 靠近拿剑（解锁攻击）→ 用攻击开宝箱 → 摩擦 / 质量 / 失效……**
> 不再需要「第一个宝箱用 E 开」的例外。

## 5. UI 提示

`PlayerVitalsPresenter` 在 `PlayerVitals.uxml` 里多了一个 `unlockToast` 标签，
订阅 `PlayerProgress.AbilityUnlocked / AttributeUnlocked / RelationUnlocked`：

- 解锁能力：爬墙跳 / 二段跳 / 攻击 / 飞刀
- 解锁规则属性：重力 / 时间 / 摩擦 / 质量 / 伤害·生命 / 因果
- 解锁规则关系：反转 / 失效 / 恒定 / 增强 / 削弱

提示 2.4 秒，最后 0.35 秒淡出；没有 `PlayerProgress` 的场景（例如 `Test_RuleSystem`）只打 Log，不报错。
