# 《规则游戏》策划案

> **项目**：26TapTap聚光灯 GameJam
> **活动主题**：涌现（Emergence）
> **引擎**：Unity（2D）
> **版本**：v3.0 · 2026-10-04
> **开发周期**：2026-10-01 ~ 10-21（21 天）

---

## 一、概述

### 1.1 一句话概念

玩家是一个和 NPC 受同样物理限制的角色，但能**暂停游戏、用词条拼规则**。
规则一经拼出，便**在一定时间内对整个世界生效**——玩家、敌人、子弹、石头全部随之改变。
玩家在关卡中与**同样持有规则之力的敌人**争夺规则，达成关卡的明确终点。

### 1.2 核心公式

**简单规则 + 多主体交互 + 玩家间接干预 = 复杂结果**

### 1.3 基本信息

| 项 | 内容 |
| **主题契合** | 涌现 |
| **形态** | 单机，2D 横版，关卡制平台动作解谜 |
| **平台** | Windows / 移动端（依活动要求上架 TapTap） |
| **联网** | **禁止任何联网功能**（官方硬性要求） |
| **操作** | 方向键移动 + 跳跃 + 攻击 + 暂停拼规则 |
| **单关时长** | 约 10 分钟 |
| **玩家数** | 单人 |

### 1.4 核心体验

三层乐趣，按优先级排序：

| 层级 | 体验 | 来源 |
| **1. 爽感** | 拼出一条规则，**看着整个世界因此改变** | 规则作用于世界本身 |
| **2. 解谜** | 想到规则组合，找到答案后的成就感 | 规则 × 关卡的组合 |
| **3. 争夺** | 和会改规则的敌人抢夺规则主导权 | 敌人机制 |

> 🔑 **核心判据**：**乐趣来自「世界变了」，不是「手不听话了」。**
> 这条判据贯穿整个设计——例如它排除了「方向反转（操作颠倒）」这类规则，因为那改变的是玩家的手，不是世界。

## 二、规则系统

> 这是整个游戏的核心系统。完整格位表见 [规则矩阵.json](规则矩阵.json)。

### 2.1 词条分类

| 类型 | 内容 | 数量限制 |
| **属性词条** | 重力、时间、摩擦、质量、关系、伤害/生命、因果 | 每种只有一个 |
| **关系词条** | 反转、失效、恒定、增强、削弱 | 可以有多个 |

**属性 7 种 × 关系 5 种 = 35 种基础规则**

### 2.2 拼法

**属性 + 关系 = 一条规则**

| 示例 | 效果 |
| 重力 + 反转 | 重力反转，g 变为负值 |
| 时间 + 恒定 | 时停 |
| 摩擦 + 失效 | 无摩擦力，像在冰面上 |

### 2.3 规则的四个特性

| 特性 | 内容 |
| **通用** | 不指向具体实体，**对所有实体生效** |
| **限时** | 拼出后生效一段时长，到期自动失效 |
| **全局** | 影响整个关卡 |
| **地形例外** | 重力等属性只对**可移动实体**生效，地形不受影响 |

> 💡 **「通用」是整个设计的基石**：规则改的是世界的物理法则，而不是某个角色的属性。
> 例：重力反转后，不仅玩家飞起来，**靠重力堵上的门也会上漂**——这种机制之间的意外耦合，才是涌现的发生地。

### 2.4 生效时间分档

| 档位 | 适用属性 | 时长 | 理由 |
| **永久** | 摩擦、质量 | ∞（关卡内） | 改变的是世界的持续属性，不破坏可玩性 |
| **长时限** | 重力 | 30-60 秒 | 重力是场景叙事的核心，给足时间体验「世界变了」 |
| **短时限** | 时间、伤害/生命、因果 | 5-15 秒 | 一旦永久生效游戏即失衡（一直时停、双方永远打不死） |

> ⚠️ **实现要点**：规则失效时**必须有过渡**——重力用 0.3-0.5 秒插值恢复，不能瞬间跳变，否则玩家会「莫名其妙摔死」。

### 2.5 规则的状态模型

规则有三种状态，跨关卡与重开关卡时的行为各不相同：

| 状态 | 含义 | 重开关卡时 | 切换关卡时 |
| **已解锁** | 玩家拿到过这个词条 | 保留 | 保留 |
| **当前激活** | 规则正在生效中 | **清空** | 存入存档的「跨关卡激活」列表 |
| **世界影响** | 世界因此发生的改变 | **重置**（回到设计初态） | 重新应用 |

> ✅ **核心原则：只持久化「已解锁」与「激活历史」这两份小数据，绝不持久化世界的物理状态。**
> 重开关卡时世界回到设计初态，再把激活的规则重新应用一遍——干净、可预测，天然避免「存档被玩坏」。

### 2.6 规则权威模型

**玩家与敌人双方都能改规则**，因此需要定义权威模型。

✅ **采用单一规则表**：全局只有一张规则表，双方往里写，**后写的覆盖先写的**。

| 考量 | 说明 |
| 实现最简 | 规则系统架构不变，仍是「一张表 + 查询接口」 |
| 天然产生争夺 | 这正是游戏想要的张力 |
| 挫败可控 | **用视觉提示规避**：敌人改规则时屏幕显示对应色调，玩家看得见就不会觉得莫名其妙 |

### 2.7 词条获取

| 阶段 | 提供方式 |
| **开局** | 给一个**完整的「属性 + 关系」对** |
| **之后** | 每次解锁**一个属性 + 一个关系** |

**组合数随进度增长**：已解锁 A 个属性、R 个关系 → 可配置 **A×R** 种规则。

| 进度 | 组合数 |
| 开局 | 1 |
| 第 2 次解锁 | 4 |
| 第 3 次解锁 | 9 |
| 第 4 次解锁 | 16 |
| 第 5 次解锁 | 25 |

> ✅ **建议在拼装界面显示「当前可组合 N 种规则」**——玩家每次解锁都能看到数字跳跃，
> **这是主题「涌现」最直接的可视化，且几乎零成本。**

**获取途径**：捡到、完成挑战、击败敌人、解决谜题、初始解锁。
可能存在循环依赖，但一定有另一条路。

## 三、玩家角色

| 项 | 内容 |
| **物理设定** | 跑跳的物理角色，**和 NPC 受完全相同的规则约束** |
| **限制** | 不能直接命令 NPC |
| **唯一特权** | **暂停游戏，拼规则** |
| **风险** | 自己也会被规则影响，甚至因此死亡 |
| **目标** | 回收规则之力 |

### 3.1 玩家控制器

**技术选型：Kinematic Rigidbody2D**

| 考量 | 说明 |
| 手感可控 | 移动完全由代码控制。Dynamic 刚体的手感由物理引擎决定，21 天内难以调优 |
| 代价 | 需自己读取 `Physics2D.gravity` 作用于玩家（约 10 行代码） |
| **额外收益** | 重力规则改的是全局值，**所有「自己接重力」的角色（含敌人）自动读到新值**——既实现「规则作用于世界本身」，又保住手感 |

> ⚠️ **暂停的实现约束**：**不能用 `Time.timeScale = 0`**。
> Unity 官方说明：取消暂停的瞬间，用 `unscaledDeltaTime` 移动的物体**会瞬移穿过碰撞体**。
> 正确做法：`Physics2D.simulationMode = SimulationMode2D.Script` + 手动调用 `Physics2D.Simulate(dt)`。

### 3.2 操作

| 操作 | 按键 |
| 移动 | 方向键 / 摇杆 |
| 跳跃 | 空格 / A |
| 攻击 | J / X |
| **暂停拼规则** | ESC / 手柄 Start |

## 四、能量系统

| 项 | 内容 |
| **用途** | 拼装规则消耗能量 |
| **恢复来源 1** | **场景中的能量道具** |
| **恢复来源 2** | 击杀敌人 |
| **恢复来源 3** | **回收规则之力**（Boss / 关键敌人，大量） |

> 💡 **设计意图**：场景道具让「恢复」本身成为一条关卡设计线索——「那个角落有能量，但要先改规则才拿得到」。
> 同时**保证纯解谜路线可行**（不强制战斗）。

## 五、敌人

### 5.1 核心设定：敌人也持有规则之力

**玩家是去回收规则之力的；敌人是同样持有规则的争夺方。**
这不是单纯的「打怪」，而是**规则的争夺战**。

> 🔑 **这个设定一举解决两个问题**：
> ① **叙事合理性**——敌人为什么特殊？因为它是另一个「改规则的人」；
> ② **防击穿**——规则系统有能力把战斗整个抹掉（玩家拼出「伤害失效」即可），而「敌人也改规则」让战斗始终存在对抗。

### 5.2 敌人分级

| 类型 | 数量 | 改规则能力 |
| **普通小怪** | 4-5 种 | ❌ 不改规则，只是吃规则影响 |
| **精英小怪** | （含在上行） | ⚠️ **局部改**，如进战斗时把摩擦变高 |
| **Boss** | 1-2 种 | ✅ **主动改规则**，阶段性改规则逼玩家应对 |

### 5.3 小怪设计原则

**用「对规则的不同响应」区分，而非外形和血量。**

| # | 敌人 | 对规则的特殊响应 | 玩法意义 |
| **1** | 普通小怪 | 完全吃规则 | 基准参照物 |
| **2** | **盘踞者** | **重力效果大减**（抓紧地面） | 不能靠改重力绕开它 |
| **3** | **浮空者** | 本身不受重力，但吃其他规则 | 重力无效，逼玩家换一条规则 |
| **4** | **规则窃贼**（精英） | **会主动改规则** | 规则争夺的直接体现 |
| **5** | **镜像体** | 与玩家共享规则状态 | 逼玩家用「对自己也不利」的规则 |

> ✅ **三大好处**：
> ① **美术成本低**——可共用骨架动画，靠颜色/特效/行为区分；
> ② **与核心机制强绑定**——每种敌人都在教玩家「规则的边界在哪里」；
> ③ **免疫是「设定」而非「规则失效」**——符合核心理念。

### 5.4 免疫的实现原则（重要）

**免疫必须通过实体自身的设定体现，不能通过规则系统强制不生效。**

| ❌ 错误做法 | ✅ 正确做法 |
| `if (enemy.isImmune) skipRule();` | `if (enemy.isGrounded) gravityEffect *= 0.1f;` |
| 在**规则系统**里加特例 | 在**实体属性**里加特性 |

> **落地原则：规则系统永远不做特例判断，特例全部写在实体自己的物理属性里。**
>
> 例：盘踞者**不是**「重力规则对它无效」，**而是**「它抓紧了地面，所以不会飘」——
> 这是世界内的合理解释，规则本身没有失效。

### 5.5 Boss 设计

**Boss 是「改规则的对手」。**

| 阶段 | Boss 行为 | 玩家应对 |
| 阶段 1 | 改一条**对玩家不利**的规则（如摩擦变大） | 用自己的一条规则**覆盖**它 |
| 阶段 2 | 改第二条规则 | 组合使用 |
| 阶段 3 | 试图**同时改两条** | 用最优组合抢回主导权 |

> ✅ **完全复用规则系统**：Boss 的「改规则」与玩家的「拼规则」**调用同一接口**。
> 不需要任何特殊战斗逻辑，只需一个「AI 决定何时改哪条规则」的决策器。
>
> 💡 **玩家怎么赢**：不是靠伤害打死 Boss，而是**在规则争夺中压制它**。

### 5.6 战斗形式

**采用 A + C 组合**：

| 组成 | 内容 |
| **A 极简战斗** | 跳跃踩踏 + 一个近战攻击 |
| **C 解谜优先** | 「敌人」同时是**会吃规则影响的障碍**——石像堵路，重力反转后飘走，路就通了 |

> ✅ **A 与 C 实现上是同一套实体的两种用法**，不需要写两套系统。
> **A 提供爽感，C 提供规则主导权。**

### 5.7 关键约束：敌人必须走同一套规则查询

- 敌人读同一个 `Physics2D.gravity`、走同一条规则查询接口
- **做到这点，「重力反转后敌人也飘起来」自动生效，不需要为敌人写任何额外代码**
- 若敌人不吃规则，则**既付出双倍代价，又废掉核心卖点**

### 5.8 敌人 AI

Unity 没有 UE 那样的 `AIController`。2D 平台游戏**不需要 NavMesh**。

**采用简单状态机**：

| 状态 | 行为 |
| **巡逻 Patrol** | 在两点间来回移动 |
| **追击 Chase** | 朝玩家方向移动 |
| **攻击 Attack** | 进入范围后出手 |

**感知**：用 `Physics2D.Raycast` 检测视野与前方障碍，`Physics2D.OverlapCircle` 检测攻击范围。

> 📌 首版**不做「同伴」类 NPC**（跟随 AI 在平台游戏中易卡墙角、掉队，成本高收益低）。

## 六、关卡设计

### 6.1 结构

| 项 | 内容 |
| **形态** | 关卡制 + 大地图（具体结构待定，见第九章） |
| **单关时长** | 约 10 分钟：4-5 分钟探索规则和机制，5-6 分钟操作通关 |
| **关卡关系** | 相对独立，**规则通过存档的「跨关卡激活」列表延续** |
| **示例** | 第 2 关开重力反转 → 第 4 关才能看到飞起来的物品 |

### 6.2 目标

- 关卡**预设的明确终点**，设计师提前设计好
- （可选）**回收规则之力**作为关卡内的次级目标

### 6.3 失败与重试

| 项 | 内容 |
| **时间限制** | 无 |
| **边界失败** | 飘出屏幕边界 = 失败 |
| **死档定义** | 玩家意识到这局没戏了 |
| **重开** | 该关卡完全重置（世界回到设计初态，规则激活清空） |

> ⚠️ **需要补充的设计**：B4 假设「玩家自己意识到没戏了」，但**玩家未必意识得到**。建议补：
> ① 随时可用的重开入口（不藏在菜单里）；② 软锁提示（检测到当前规则下不可解时提示重置）；③ 撤回上一次规则。

### 6.4 难度曲线

| 关卡 | 难度定位 |
| 第 1 关 | **教学**：只给「重力反转」，必过 |
| 第 2 关 | **巩固**：重力反转 + 新应用场景 |
| 第 3 关 | **引入第二条规则**（如摩擦） |
| 第 4 关 | **组合**：需同时用两条规则 |
| 第 5 关+ | **自由**：给多条规则，玩家自选解法 |

> 🔑 **核心原则**：**难度应该来自「想不到组合」，而不是「操作难」。**
> 如果玩家通关靠的是手速而不是脑子，那规则系统就白做了。

## 七、教学与引导

**原则：靠关卡设计引导，不用大段文字。**

| 原则 | 落地方式 |
| **单变量隔离** | 一关只引入一个新概念 |
| **先给工具，后给难题** | 第 1 关只给「重力」+「反转」，必须拼出来才能过关 |
| **让结果自己说话** | 不弹窗解释，玩家拼出重力反转 → 看到石头往上飘 → 自己明白 |
| **每个新词条配一个只能用它解决的关卡** | 强制玩家理解新词条语义 |
| **教学关要能「反证」** | **不知道这条规则就一定过不去**（否则教学失效） |
| **组合循序渐进** | 不一次性开放所有关系；「失效」等强关系放中期 |

> 📌 **成本校准**：Baba Is You 是单人约 2 年全职做 231 关，且系统复杂度远低于本作。
> 教学关链就是 **3-5 关**，不要更多。**前 3 关决定了评委能否玩懂。**

## 八、叙事

### 8.1 叙事方式：世界状态叙事

**不靠对话讲故事，靠玩家「看到」世界因规则而变。**

| 层次 | 内容 |
| **环境叙事** | 关卡本身就是故事。第 2 关重力反转 → 第 4 关地形倒挂，建筑在天上 |
| **NPC 状态叙事** | NPC 记得世界变了，根据**世界状态**触发台词 |
| **元叙事** | 玩家就是改规则的人。结算画面显示「你改了多少条规则，世界变成了什么样」 |

### 8.2 NPC

| 项 | 内容 |
| **角色** | 灵活：障碍、工具、观察对象、同伴 |
| **规则约束** | **和玩家受同样的规则约束** |
| **「智能」实现** | **不需要 AI**——读当前世界状态，播一句对应台词即可 |

> 💡 NPC 的「记忆」可以完全是假的：他不真的理解世界，只是在世界状态变化后读一下当前状态，播一句话。
> **成本极低，效果好。**

### 8.3 台词系统

| 项 | 约束 |
| **规模** | **20-40 条 barks**（参照 Exocolonist 是 1800 条 + 60 万字，21 天必须大幅缩减） |
| **数据源** | 存档的**激活历史**——支撑「刚才我怎么突然飞起来了」这类回顾式台词 |
| **条件绑定** | ⚠️ **必须绑定「当前世界状态快照」，不能绑定历史事件** |
| **原因** | 否则会出现「NPC 在第 5 关提到玩家第 6 关才开的规则」的时序穿帮 |
| **工具** | **不自研对话引擎**，用 Yarn Spinner 或 CSV + 条件求值 |

**三层防御**（避免穿帮）：
1. **L1** 台词表外置为 CSV/JSON，不写死在代码里
2. **L2** 启动期做引用校验（规则 ID 存在、变量已初始化、无重复 id）
3. **L3** **无条件兜底 bark**——绝不允许 NPC 沉默或显示占位符

### 8.4 结局

**通关结算不显示「你赢了」**，而是回顾玩家的行为：

- 你改了多少条规则
- 世界变成了什么样
- （可选）你用 N 条规则通关，最少是 M 条

> 这是元叙事的落点，**成本极低（一个结算画面），但能显著提升「完成度感」**，且顺带提供重玩价值。

## 九、UI 与反馈

### 9.1 必需 UI

| UI | 说明 | 优先级 |
| **规则拼装界面** | 暂停时打开，核心交互 | 🔴 必须 |
| **当前生效规则列表** | ⚠️ **常驻显示** | 🔴 必须 |
| **规则剩余时间** | 有限时规则则必须可见 | 🔴 必须 |
| **能量条** | 拼装消耗的能量 | 🔴 必须 |
| **词条库存** | 未使用的词条 | 🟡 建议 |
| **可组合规则数** | 「当前可组合 N 种规则」 | 🟡 建议（主题可视化） |

> 🔴 **「当前生效规则」的常驻显示是最容易被忽略但最重要的一项。**
> 因为规则会跨关卡保留，**玩家自己会忘**。忘了之后遇到怪事，他会归因于游戏 bug 而不是自己改过的东西。

### 9.2 规则生效的反馈

| 环节 | 表现 |
| **拼装完成** | **摄像机拉近特写**（建议用 Cinemachine） |
| **同时** | **全屏特效**（后处理 / 全屏遮罩 + 色偏） |
| **特写期间** | ⚠️ **世界暂停或极慢**，特写结束后世界才开始运动 |
| **时长** | 建议 **0.5-1 秒**（太长会打断节奏，每关要触发多次） |

> ⚠️ **设计权衡说明**：特写与「暂停解除后立刻操作」有潜在冲突（特写占 1 秒，这 1 秒世界在动吗？）。
> 当前决定：**特写期间世界静止**，让「拼装 → 生效」有一个清晰的节拍。
>
> ✅ **额外收益**：官方硬性要求提交的实机录屏与截图**不能用过场动画/读条/菜单**，
> 而「规则生效特写」是**游戏内实时画面**，可作提交材料的首选素材。

## 十、存档系统

```json
{
  "已解锁词条": {
    "属性": [
      "重力",
      "摩擦"
    ],
    "关系": [
      "反转",
      "失效"
    ]
  },
  "跨关卡已激活规则": [
    "重力反转"
  ],
  "激活历史": [
    {
      "rule": "重力反转",
      "关卡": 2
    }
  ],
  "进度": {
    "当前关卡": 3,
    "通关标记": [
      1,
      2
    ]
  },
  "能量": 50
}
```

> **设计原则**：**只持久化小数据，绝不持久化世界的物理状态。** 重开关卡时世界回到设计初态，再把激活规则重新应用一遍——天然避免「存档被玩坏」。
| 项 | 决定 |
| **存档粒度** | 按关卡存 |
| **时机** | **自动存档**（每关开头/结尾），不做手动存档 |
| **激活历史** | 供 NPC 台词引用 |

## 十一、技术方案

### 11.1 引擎与架构

| 项 | 内容 |
| **引擎** | Unity（2D） |
| **玩家控制器** | Kinematic Rigidbody2D |
| **数据层** | ScriptableObject（每条规则一个 .asset 文件，策划可直接改数值） |
| **规则系统** | 单例 + `IsRuleActive(ruleId)` 查询接口 + `OnRulesChanged` 事件 |
| **依赖方向** | Gameplay → Core → Data（单向，不可反向） |

> ⚠️ **2D 项目必须用 `Physics2D.*` 而不是 `Physics.*`**——Unity 的 2D 与 3D 物理是两套完全独立的系统。
> 物理代码必须写在 `FixedUpdate()` 里，不是 `Update()`。

### 11.2 规则系统的实现要点

```csharp
// 重力类：直接改全局变量，所有刚体自动受影响
Physics2D.gravity = new Vector2(0, -9.81f * multiplier);
```

| 要点 | 说明 |
| **全局载体** | `Physics2D.gravity` 是唯一的「真全局」量，改一行所有实体响应 |
| **摩擦/质量** | **没有全局变量**，必须遍历受影响的对象 |
| **特例禁止** | 规则系统**不做任何特例判断**，特例全部写在实体属性里 |

> ✅ 这正是「规则不指向具体实体，对所有实体生效」在代码里的落地方式。

### 11.3 官方约束（硬性）

| 约束 | 说明 |
| **禁止联网** | 游戏中不允许带有联网功能。**本地多人明确允许**，局域网联机/云存档/联网排行榜禁止 |
| **禁止广告** | 活动期间不可接入任何形式的广告 |
| **必须上架** | 需在 TapTap 完成上架并通过审核；含安卓时须通过 TapPlay 稳定性检测 |
| **开发者日志** | ≥5 篇，且不能一天内连发（全程参与奖条件） |
| **素材说明** | 使用第三方素材需附比例说明文档；AI 生成资产需附说明文档 |
| **提交截止** | 10/21 12:00 前**上传并通过审核**（官方建议 10/18 前提交） |

## 附录 A · 已废弃的设计（保留决策记录）

以下属性与关系经讨论后**决定砍掉**。保留记录是为了说明「为什么不做」：

| 项 | 决定 | 理由 |
| **空间属性** | ❌ 整个砍掉 | 六个格位技术形态完全不一致：关卡镜像是编辑器操作、距离缩放需改整个坐标系、「穿墙」会让所有关卡失去边界约束（可解性上最危险的一条） |
| **方向属性** | ❌ 整个砍掉 | 它改变的是**玩家的输入映射**，而非世界的物理法则。重力反转让世界变了，方向反转只让手不听话。且缺少全局载体，物理上无法「对所有实体生效」 |
| **循环关系** | ❌ 整个砍掉 | 一次性消掉 9 个格位；顺带解决时间循环、因果循环两个高风险项；且循环规则的计时器与「暂停拼规则」在语义上冲突 |
| **时间倒流 + 物理倒放** | ❌ 不可行 | Unity 内置物理是非确定性的，物理倒放在数学上不成立。若要做时间倒流，只能走「状态快照回放」 |

### 一条可复用的判据

**一条规则是不是「好规则」，看它改变的是世界，还是玩家的手。**

| 改变世界 ✅ | 改变玩家的手 ❌ |
| 重力、摩擦、质量、时间、伤害/生命、因果、关系 | **方向** |

> 这条判据与主题直接相关：**只有世界变了，才会涌现出新的解法。**
