# 规则轮盘接入

基于已合入 `main` 的 P2/P3 正式玩家、规则目录与释放服务实现。按新策划案批注采用慢时间选择：世界继续运行，玩家输入临时交给轮盘；不用旧白盒的暂停与预览扣费控制器。

## 试播

执行 **RuleGame → Rule Wheel → Open Test Scene**，或打开 `Assets/_Project/Scenes/Test_RuleSystem.unity`，进入 Play Mode。

轮盘直接接入队友的 `Test_RuleSystem.unity`：使用该场景当前的正式主角和 Animator，保留地形、P3 玩家输入、碰撞层、手感配置以及 P2/P3 调试面板。接线只添加轮盘、镜头接管、试用解锁查询和托球表现，不改 Build Settings。旧 `Test_RuleWheel` 是早期方块副本；后续手动验证使用正式测试场景。

- A/D 移动，Space 跳跃，鼠标左键近战。
- 按住 Shift 进入约 0.001 倍慢时间，世界近乎定格，镜头推近玩家。内圈选属性，悬停后在对应属性外侧展开关系弧；内外两圈共用圆心，外圈弧的中点始终对齐所选属性的径向中线，上下边缘不限制外圈角度。内圈始终显示，移到外圈关系后左键释放。没有单独的“关系”框或连接线。
- 松开 Shift 或按 Escape 取消；右键收起二级关系扇；鼠标直接返回一级可切换属性。成功释放后必须先松开 Shift，才能再次打开。
- 手柄用右扳机进入、右摇杆悬停属性，X 把导航切到关系扇，摇杆回中后选择关系并再次 X 释放，B 返回一级。两个轮盘保持同时显示。
- 正式测试场景沿用 P2/P3 调试面板清理规则、查看能量。旧副本的 R 键只属于试播工具，不作为正式重开关卡服务。

这里把「按 Shift 时」具体落实为长按模式，松开取消。它是可体验的交互约定，若团队决定改成开关式，改输入适配即可，选择状态机和释放服务无需重写。

```mermaid
stateDiagram-v2
    [*] --> 关闭
    关闭 --> 属性: 按住 Shift
    属性 --> 关系: 悬停可用属性
    关系 --> 属性: 右键收起
    关系 --> 关系: 悬停另一属性
    关系 --> 关闭: 左键释放成功
    关系 --> 关系: 能量或冷却不满足
    属性 --> 关闭: 松开 Shift / Escape
    关系 --> 关闭: 松开 Shift / Escape
```

6 属性全部可见；具体可用性由当前规则目录和解锁查询决定，不在 UI 中写死某个属性不可用。显示器不生成假效果、不自行扣能量。能量不足或冷却中，失败后保留当前世界规则和选择阶段。

## 正式接入

创建 UIDocument，指定 `RuleWheel.uxml` 和 PanelSettings，添加 `RuleWheelPresenter`，绑定 P3 PlayerController、正式 RuleCatalog、已解锁查询组件、镜头来源和世界 Camera。慢时间不需要接线：轮盘直接走 P1 的 `TimeManager`。

### Inspector 接线

UIDocument 使用 `Assets/_Project/UI/RuleWheel/RuleWheel.uxml`，PanelSettings 可复用同目录的 `RuleWheelPanelSettings.asset`。布局和字体、字块配色在 UXML/USS 中维护，不需要修改释放服务。

`RuleWheelPresenter` 的引用与参数：

- `_player`：正式玩家物体上的 `PlayerController`。其同物体须有 `EntityStatus`，UI 会检查玩家是否启用及是否完全暂停。
- `_catalog`：当前规则系统使用的 `RuleCatalog`。不要另建一份只供 UI 扣费或计时的目录。
- `_unlocks`：实现 `Gameplay.Player.IRuleUnlocks` 的 MonoBehaviour；只查询属性/关系是否已经解锁。试播使用 `RuleWheelLabUnlocks`，正式场景接库存查询组件。
- （**没有时间来源字段**）慢时间直接走 P1 的 `TimeManager.Instance`：进入时 `PushScale(TimeSource.UI, _selectionScale)`，关闭时 `RemoveScale(TimeSource.UI)`。全项目只有 `TimeManager` 一处写引擎时间。
- `_cameraFocus`：实现 `IRuleSelectionFocus` 的 MonoBehaviour；示例使用 `RuleSelectionCamera`。
- `_worldCamera`：实际绘制玩家的 Camera，用来把玩家的世界位置换算成轮盘屏幕位置。
- `_selectionScale`：默认 `0.001`。它是**「选择模式」这一路来源**的倍率，由 `TimeManager` 与时间规则等其它来源乘法合成 —— 当前没有别的来源时整体倍率就是 `0.001`。进入时直接切换倍率，镜头、托球动作和 UI 使用真实时间；松开 Shift 移除选择来源。安装工具同时更新已有测试场景和 `LevelRuntime.prefab` 的序列化倍率。
- `_playerOffset`：默认 `(70, 0)`，没有托球表现时控制轮盘在玩家右侧的偏移。接入托球表现后，优先把两圈圆心对齐光球，并限制轮盘不越出屏幕边缘。

两圈在同一 650 × 650 的显示区域中绘制，圆心取区域中心。外圈以所选属性中线左右各展开 60°，五个关系中间的「恒定」与属性正对；屏幕边缘只平移整组 UI，不截断或重排外圈角度。绘制、标签位置、鼠标命中和手柄导航共用同一圆心与角度参数。

`RuleSelectionCamera` 的引用与参数：

- `_target` 指向玩家 Transform。
- 场景已有 `P3FollowCamera` 等跟随组件时，把它拖入 `_normalFollow`。选择时暂时禁用原跟随，取消或成功释放后平滑回拉，再恢复其进入前的启用状态。
- `_selectionOffset` 默认 `(1.3, 0.35)`，给右侧轮盘留空间；`_selectionSize` 默认 `2.8`，是特写时的正交尺寸；`_transitionTime` 默认 `0.18` 秒。
- 特写与回拉按非缩放时间推进。回拉完成以缩放恢复为依据；玩家边走边取消时，不会因一直追赶移动目标而永久占用镜头。
- 绑定了 `_normalFollow` 时，平时的位置由原跟随组件维护；不要再添加另一个持续写同一 Camera Transform 的跟随脚本。

### 运行链路与失败处理

1. 玩家按住 Shift，Presenter 依次接管时间（`TimeSource.UI` 来源）、输入和镜头令牌；必需引用缺失时会输出配置错误并禁用组件。
2. 内圈属性始终显示；悬停可用属性就展开同心的外圈关系弧，不执行规则、不扣能量。进入外圈和跨过中间间隙时保留属性；再次悬停其他属性会调整外圈弧的位置并清掉旧的关系选择。
3. 关系阶段读取正式目录、解锁状态、冷却和能量，显示当前可用性。目录未定义或未解锁的组合不可释放。
4. 攻击键确认后调用既有 `RuleReleaseService.TryRelease`，由 P3 请求 P2 执行规则。能量、冷却以及生效中的规则与剩余时长仍由原系统维护。
5. 成功后关闭 UI 并释放令牌；能量不足、冷却中或尚不可用时留在关系阶段并显示提示，不先扣费，也不删除已有规则。
6. 松开 Shift、Escape、失焦或禁用组件都走同一关闭路径。取消不产生规则、不扣费，关闭当帧的确认键不会再传给近战。

移动输入被临时接管时，玩家原来的 FixedUpdate 仍然执行：重力、碰撞与外部冲量继续按慢时间推进。轮盘不会调用 `EntityStatus.SetPaused`，也不接管 `Physics2D.Simulate`。

### 文件职责

运行期职责：

- `Gameplay/Scene/Rules/RuleSelectionSession` 管两级选择和可用性，使用现有 `RuleReleaseService.TryRelease`，请求成功后由 P3 结算。
- `UI/RuleWheel/RuleWheelPresenter` 读两级悬停输入、显示内容、申请与释放接管令牌；静态布局在 UXML/USS。
- `UI/RuleWheel/RuleFan` 用 Painter2D 绘制纸扇，扇区命中与标签位置共用半径、角度参数。参数可在 UI Builder 的自定义元素上调整。
- `Presentation/RuleWheel/RuleSelectionCamera` 提供临时特写和回拉。副本的 `_normalFollow` 绑定队友的 `P3FollowCamera`：只在选择与回拉期间禁用它，回拉结束后归还；平时继续使用队友原来的跟随。没有既有跟随组件时，才使用此组件内置的正常跟随。

P3 PlayerController 新增 `BlockGameplayInput()`，返回可释放令牌，只阻止输入，不阻止 FixedUpdate。最后一个令牌释放当帧仍吞掉确认输入，避免规则释放和近战同时触发。原来的 `EntityStatus.SetPaused` 仍按 P3 的完全暂停语义工作，轮盘不调用它。

## P1 与 P3 接管点

两个令牌接口放在 `Infrastructure/Shared/Interaction/`，无上层程序集依赖：

- `IRuleSelectionInputGate`：接管玩家输入，释放当帧不把确认键漏回战斗。
- `IRuleSelectionFocus`：镜头组件提供临时特写令牌；UI 不引用具体镜头类。

镜头来源通过 MonoBehaviour 引用并检查接口。失焦、禁用、取消和成功释放都统一关闭并释放令牌。

**时间不再走接口**：原先的 `IRuleSelectionTimeSource` 与试播适配器 `RuleWheelLabTimeSource` 已删除 —— 后者自己保存 / 恢复 `Time.timeScale` 与 `Time.fixedDeltaTime`，是「第二处修改时间」，与 P1 的多来源时间管理器并存时会互相覆盖，还得靠「读回值比对」猜自己那笔有没有被改掉。现在轮盘只占 `TimeManager` 的一个来源位（`TimeSource.UI`），不碰引擎全局值。`RuleWheelLabUnlocks` 仍仅供试播开放词条，正式场景替换成实现 P3 既有 `IRuleUnlocks` 的库存查询。

P1 侧不需要再为轮盘写适配器：`TimeSource.UI` 本来就是给选择模式留的来源位，`PushScale` / `RemoveScale` 已是最终形态。轮盘进入前会检查 `EntityStatus.IsPaused`，被完全暂停时不进入选择。

轮盘不修改物理步长。本项目的固定物理步长为 1/60 秒，降低时间倍率也会降低每真实秒的物理更新次数；0.001 倍模式用于让选择期的世界近乎定格，表现层继续按真实时间运行。

P3 接入时，保留 `BlockGameplayInput()` 的令牌语义。多个输入持有者并存时，只释放自己持有的阻塞；最后一个令牌释放后才恢复玩家输入。解锁查询通过已有 `IRuleUnlocks` 接口接入，不需要让 UI 依赖库存内部实现。

正式关卡接入不需要 `Development/RuleWheel`：生命/能量显示可接现有 HUD，规则选择使用 Presenter、状态机与共享接口即可。`RuleWheelLabHUD` 的 R 键仅清空规则、恢复能量，不重置角色位置或存档；销毁试播场景时会清理规则并恢复进入前的重力。

没有新增程序集；功能分别放入已有 Gameplay、UI、Presentation、Development 和 Editor。UI / Editor 增加 Input System 引用以处理输入和场景接线。


## 托球动作与柔光

执行 `RuleGame/Rule Wheel/接入托球动作与柔光（保留玩法）`，为 `Test_RuleSystem` 以及已有轮盘白盒接入 `RuleSelectionOrbView`。新场景在同一轮盘物体上添加此组件，指定 `Assets/_Project/Data/RuleWheel/RuleOrbArt.asset` 即可；它从 Presenter 读取玩家与相机，并订阅选择打开、关闭事件。

动作来自交付的“手托光球”：8 帧掏出在真实时间 0.28 秒内播放完（每帧约 35 ms），托球循环保留 8 FPS，5 帧收回使用 0.22 秒。掏出和收回的时长独立于待机帧率，不受 0.001 倍世界慢时间影响。原来把掏出也按 8 FPS 播放，每帧停留 125 ms、总长 1 秒，起手有明显停顿；现在不再共用那个帧率。

17 帧共享身体比例和脚底锚点，不执行旧剪辑的 Transform 位移或缩放曲线。选择期临时隐藏原显示并暂停原 Animator，继续保留玩家物理；关闭后归还原动画。掏出中取消会从当前帧倒放，时长按已播放比例缩短。松开 Shift 后可以立刻移动、跳跃，不因收球继续锁输入。

光球采用柔和填满的光晕、缓慢呼吸、手掌和脸侧的暖色反光、URP 2D 手灯及局部 Bloom。没有爆炸、尖刺、冲击波或抖屏。选择期临时开启当前相机后处理，收尾后恢复进入前的设置；不会写 Project Settings。2D 手灯照亮支持 2D 光照的场景材质；未接灯光的 Unlit 背景不会自动获得投影，人物本身的暖反光由专用表现材质提供。

`RuleOrbArt` 的 `DrawDuration` / `ReturnDuration` 配置掏出与收回秒数；`FramesPerSecond` 仅控制托球循环。其余配置包括图集、脚底轴心、人物高度、光球位置和材质。特效不决定规则、能量、冷却、伤害或世界时间。所有慢时间和输入令牌仍由 Presenter 管理。

图集可用 `Tools/RuleOrb/build_atlas.py` 从交付目录重新生成；统一裁切、比例与脚底锚点，避免各帧按自身包围盒缩放导致人物忽大忽小。原始 PSD、视频和序列帧保留在交付目录。
